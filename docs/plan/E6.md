#### T120. Расход вызова и таблица цен

#### T121. Отказы поставщика: «лимит исчерпан» и отказ ключа

- **Цель:** адаптеры распознают отказ по лимиту, балансу или оплате и отказ ключа и отдают их своими исходами, а SDK их не повторяет.
- **Почему:** раздел 3.7 и R84 spec. Оба SDK сами повторяют 429 дважды, и отказ по лимиту без этого стал бы сбоем ИИ.
- **Сделать:**
  - «лимит исчерпан» с причиной — по каждой строке таблицы отказов раздела 3.7;
  - отказ ключа — неверный или отозванный ключ (R84 spec): коды ответа и тексты — из документации поставщиков, с цитатой и датой в разделе 4;
  - прослойка запроса, которая не даёт SDK повторять эти отказы, а обычные 429, 408, 409 и 5xx оставляет повторам;
  - два читателя: лимит одному — исход целиком, расход ответившего остаётся;
  - тесты — по случаю на строку таблицы, на сервере тестов `httptest`;
  - architecture 3.7 и 4.
- **Как проверить:** тесты; `just ci-test`; `docs-check-repo`; `/code-review high`.
- **Разделы:** разделы 3.7, 4; R55; R84 spec.
- **Риски:** текст ответа поставщика — не контракт: страница может сменить формулировку. План называет, как адаптер узнает об этом.
- **Сделано (2026-11-11):**
  - **ошибки** — `provider.LimitError` с причиной и `provider.ErrKeyRefused`; адаптеры распознают каждую строку таблицы раздела 3.7, а 401 — как отказ ключа, кроме 401 Anthropic о запросе из браузера;
  - **повторы** — прослойка `provider.NoRetry` ставит отказу `x-should-retry: false`, и SDK его не повторяет, а обычный 429 — повторяет;
  - **пара** — исход `ask` — самый тяжёлый отказ: лимит, ключ, сбой; расход ответившего остаётся;
  - **риск** — слова ответа не контракт: при смене отказ становится сбоем ИИ, а источники сверяют перед каждым релизом (R95);
  - **документы** — R95, architecture 3.7 и раздел 4, «Отказы»;
  - **ревью** `/code-review high` — 9 находок, исправлены 7: 429 OpenAI типа `insufficient_quota` с незнакомым кодом — теперь «оплата»; слова о балансе Anthropic при коде 5xx — прослойка читает тело при любом коде от 400; оборванное чтение тела — SDK получает ту же ошибку; ответ без тела или заголовков — без паники; тесты строк 400, 401 и 402 не проверяли прослойку — прямые тесты `NoRetry`; `LimitReason` — тот же тип, что `provider.Limit`; прослойка читает не больше 64 КБ тела; неточность R95 о повторах при смене слов — исправлена. Классификацию через указатель из прослойки, а не через ошибку SDK, я оставил: у каждого адаптера один путь возврата ошибки;
  - **проверено:** тесты на `httptest` по строке таблицы у каждого адаптера — отказ отправлен один раз, обычный 429 — дважды; исходы пары; `NoRetry` напрямую; `go test` затронутых пакетов, `just lint`, `docs-check-repo`.
