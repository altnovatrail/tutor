#### T120. Расход вызова и таблица цен

- **Цель:** сообщение о расходе каждого вызова, таблица цен с кешем и датой, ожидаемая и худшая цена каждого вида вызова и ограниченный предел выхода.
- **Почему:** по расходу `api` считает квоту ИИ платформы и резерв перед вызовом (R11 api; architecture 3.6 spec), а сейчас в `provider.Response` нет кеша, а у моделей — только цены входа и выхода (раздел 3.7).
- **Сделать:**
  - в `provider.Response` — токены записи в кеш по сроку хранения и чтения из кеша; у OpenAI токены кеша вычитаются из входа (раздел 3.7);
  - сообщение о расходе: по записи на вызов модели, поставщик и модель из ответа, токены, точен ли счёт, оценка в долларах. Оборванный ответ — по худшему случаю; ответ без JSON — с записью; вызов, которому отказали по лимиту, — без записи;
  - таблица цен: на каждую допущенную модель — вход, запись в кеш по сроку, чтение из кеша, выход, длинный контекст, где он есть, и дата прочтения. Растёт из цен адаптеров, а не второй копией; цены — со страниц Pricing поставщиков, с цитатой и датой в разделе 4;
  - ожидаемая цена вида вызова — по токенам вида в замерах, — худшая — по наибольшему входу и `MaxOutputTokens`, и ограниченный `MaxOutputTokens` каждого вида вызова продукта (Д76 RUN.md `spec`);
  - architecture 3.7 и 4.
- **Решить при планировании:** откуда ожидаемые токены вида — постоянные из замеров в коде (рекомендация) или файл.
- **Как проверить:** тесты: запись на каждого читателя, вычет кеша OpenAI, худший случай, ответ без JSON; `just ci-test`; `docs-check-repo`; `/code-review high`.
- **Разделы:** разделы 3.7, 3.12, 4; R55; architecture 3.6 spec; R11 api.

#### T121. Отказы поставщика: «лимит исчерпан» и отказ ключа

- **Цель:** адаптеры распознают отказ по лимиту, балансу или оплате и отказ ключа и отдают их своими исходами, а SDK их не повторяет.
- **Почему:** раздел 3.7 и R84 spec. Оба SDK сами повторяют 429 дважды, и отказ по лимиту без этого стал бы сбоем ИИ.
- **Сделать:**
  - «лимит исчерпан» с причиной — по каждой строке таблицы отказов раздела 3.7;
  - отказ ключа — неверный или отозванный ключ (R84 spec): коды ответа и тексты — из документации поставщиков, с цитатой и датой в разделе 4;
  - прослойка запроса, которая не даёт SDK повторять эти отказы, а обычные 429, 408, 409 и 5xx оставляет повторам;
  - два читателя: лимит одному — исход целиком, расход ответившего остаётся;
  - тесты — по случаю на строку таблицы, на сервере тестов `httptest`;
  - architecture 3.7 и 4.
- **Как проверить:** тесты; `just ci-test`; `docs-check-repo`; `/code-review high`.
- **Разделы:** разделы 3.7, 4; R55; R84 spec.
- **Риски:** текст ответа поставщика — не контракт: страница может сменить формулировку. План называет, как адаптер узнает об этом.

#### T122. Проверка своего ключа

- **Цель:** вызов проверки своего ключа без содержания ученика и его исходы.
- **Почему:** `api` проверяет ключ при подключении через `tutor` и к поставщикам в обход него не ходит (R84 spec; Д78, Д101 RUN.md `spec`).
- **Сделать:**
  - вызов без работы и без данных ученика, ключом и поставщиком из запроса; исходы — «принят», «неверный», «у ключа нет прав» и «поставщик не ответил»;
  - чем проверять — бесплатным запросом поставщика, если он есть: документация с цитатой и датой в разделе 4;
  - поставщики, открытые своему ключу, `api` берёт у функции допуска T112;
  - architecture 3.7 и 3.10.
- **Решить при планировании:** запрос проверки у каждого поставщика и что он стоит.
- **Как проверить:** тесты на `httptest` по исходу; ключ не попадает ни в ошибку, ни в журнал; `just ci-test`; `docs-check-repo`; `/code-review high`.
- **Разделы:** разделы 3.7, 3.9, 3.10; R84 spec.
